# 教学规范与知识验收标准

## 统一结构

每一讲都按以下顺序组织，不得省略：

### 1. 概念
- 准确定义。
- 解决什么问题。
- 与相邻概念的区别。
- 一个直观例子。

### 2. 原理
- 从直觉到数学表达。
- 公式中每个符号的含义、单位和坐标约定。
- 算法成立的前提。
- 失败条件与反例。

### 3. 数据结构
- 输入/输出 schema。
- 数据类型、维度、单位、坐标系。
- 元数据、版本、样本 ID 和数据血缘。
- 常见格式与字段解释。

### 4. 算法
- 完整步骤。
- 关键参数及其影响。
- 时间/空间成本的定性分析。
- 替代算法及选择理由。

### 5. 工程实现
- 依赖安装与版本。
- 可运行的最小示例。
- 输入准备、执行命令、输出检查。
- 异常处理、日志、可复现性。
- 明确标注教学伪代码与可运行代码的区别。

### 6. 评价指标
- 指标公式、单位和方向（越大越好/越小越好）。
- Ground Truth 要求。
- 归一化、坐标对齐、采样和阈值协议。
- 指标局限和互补指标。

### 7. 实际案例
优先使用 3D 角色生成、混元 3D、场景生成、Blender、UE、COLMAP 等场景。真实项目数据与教学假设必须分开。

### 8. 面试追问
至少包含：
- 基础定义题。
- 原理推导题。
- 工程排障题。
- 评测方案题。
- 反例/局限题。
每题提供回答结构和常见追问。

### 9. 小测
- 8–12 道客观题。
- 至少 3 道开放题。
- 提供评分维度和错误后的补课路径。

## 质量标准

- 不允许只罗列名词；必须解释“为什么”。
- 不允许公式无变量定义、无单位或无适用条件。
- 不允许把相似但不同的概念混为一谈。
- 不允许把 CLIP/重投影误差等单项指标当作完整 3D 质量结论。
- 不允许在无 Ground Truth 时声称获得真实几何误差。
- 不允许把示意图、假设数字或伪代码称为实测结果。
- 工程代码需说明输入假设、坐标约定和已知局限。
- 每讲结尾更新课程进度，但“已覆盖”不等于“已掌握”；掌握状态由练习和测验决定。

## 学习者验收等级

- 未开始：尚未教学。
- 已覆盖：已讲解，但未完成验收。
- 练习中：已完成部分代码或题目。
- 已掌握：能独立解释、推导、实现并回答追问。
- 待复习：测验或实操暴露明显薄弱点。

## 术语与版本约定

首次出现术语时给出英文全称、中文解释和缩写。公式应声明坐标系、单位和误差定义。工具命令应记录工具版本；论文结论应注明论文名称/年份，必要时附原始来源。
