# 第 22 讲实验：分组划分、训练侧拟合与泄漏审计

这是一个 Python 标准库教学实验。**输入是合成的 3D 资产元数据，不包含真实 Mesh、渲染图或神经网络训练。**它演示的是数据集构建和泄漏检查，不把玩具实验的百分比描述成真实 3D 模型效果。

## 任务与输入约定

任务设定为：**在已知三个类别内，对训练时未见过的资产家族进行类别预测。**因此，本实验要求家族在 train、validation、test 之间互斥。若实际任务是同一场景的新视角重建，其允许共享的条件需要另定，不能直接套用这里的家族规则。

输入由 `make_rows()` 确定性生成：

- 三类：chair、lamp、table；每类 40 个资产家族，共 120 个。
- 每个家族设想有 3 个 view，每个 view 有 2 个 LOD，共 6 条记录。
- 总共 720 条记录；每条记录具备唯一 `sample_id`。
- `family_id` 由合成器明确指定，同一家族内只有一个类别。这不是近重复检测算法推断出来的关系。
- `source_id` 为两个人工来源标签，均允许进入三个集合；实验不评估“未见来源”泛化。
- 一个数值特征 `bbox_diagonal_mm`，shape 为 `(720, 1)`，单位毫米；它是人为设置的包围盒对角线代理值，没有从真实网格测量。
- 本实验没有三维坐标输入，因此不涉及坐标轴或左右手变换。view/LOD 只是元数据，未实际渲染或简化网格。

关键字段：

| 字段 | 含义 |
|---|---|
| sample_id | 一条 view/LOD 记录的唯一 ID |
| asset_id | 逻辑资产 ID |
| family_id | 本任务禁止跨集合共享的家族 |
| class_name | 分类标签 |
| source_id | 人工来源标签 |
| view_id / lod | 合成派生记录的索引 |
| bbox_diagonal_mm | 用于展示训练侧标准化的单一合成特征 |

JSON 摘要使用本代码规定的 UTF-8、键排序、固定分隔符和禁止 NaN 的序列化。**它不宣称完整实现 RFC 8785，也不保证跨语言/跨 Python 版本的随机划分一致。**报告保留实际 Python 版本、代码 SHA-256、seed、候选数据摘要和实际成员清单。

## 两种划分

### 1. 故意错误的行级随机划分

先将 720 个 sample_id 排序，再用固定 seed 22 打乱，按 70% / 15% / 15% 分配。

三份集合的 sample_id 没有交集，但同一资产家族的不同 view/LOD 可进入不同集合。对“新家族泛化”任务，这是泄漏。

### 2. 正确的分组与类别分层

先按 family_id 聚合，再在每个类别内打乱家族，把整个家族分配到一个集合：

- 每类 28 个家族进入 train；
- 每类 6 个家族进入 validation；
- 每类 6 个家族进入 test。

本例每组恰好 6 行，因此组数比例和记录数比例恰好一致。代码是“每组单类别”的教学特例，**不是通用 StratifiedGroupKFold 实现，也不是能同时满足任意多约束的优化器**。面对大小不一、跨类别、多关系约束的组，需另设算法和可行性检查。

若一个类别只有 2 个独立家族，而协议要求三份集合都包含该类别，脚本明确拒绝。它不会把同一家族拆开来凑齐三个集合。

## 训练侧拟合与增强

`fit_preprocessor()` 要求传入的实际拟合 sample_id 集合与冻结 train 成员集合相等。它检查真实 ID，不仅检查一个声称 `fit_split=train` 的字段。

它对 504 条训练记录拟合一个特征的均值与总体标准差：

- 均值约 **1160.857143 mm**；
- 总体标准差约 **295.126855 mm**。

所有集合使用同一训练均值和标准差变换：

\[
z=\frac{x-\mu_{\mathrm{train}}}{\sigma_{\mathrm{train}}}.
\]

输出无单位。训练变换后均值约为数值误差量级的 0；验证和测试均值不需要也不应被分别强制归零。

脚本将所有 validation/test 特征增加 10,000 mm，再用相同训练 ID 拟合，**训练统计完全不变**。这是实际执行过的检查。若错误地用全体修改后数据拟合，均值变成 4158.5 mm；这个反事实数值只演示污染，不用来变换正式测试输入。

`augment_from_train()` 只接受训练父样本，保留家族与类别，并记录 parent_id。示例把代理特征乘以 1.01，**没有对实际 Mesh 做几何增强，也没有验证真实任务标签不变性**。

报告中保留 3 条增强元数据示例，它们位于基础 split 清单之外；它们没有被静默添加进冻结的 720 条成员清单，也没有用于拟合上述统计。真实训练若使用这些派生记录，应另行冻结训练输入与增强配置。

## 八种故障注入

| 输入违规 | 实际拦截原因 |
|---|---|
| 缺少 family_id | `missing_row_fields` |
| 重复 sample_id | `duplicate_sample_id` |
| 有记录未被分配 | `unassigned_sample` |
| 同一 sample_id 进入多个集合 | `duplicate_or_cross_assigned_sample` |
| 同一家族跨集合 | `family_split_leakage` |
| 用全部记录拟合预处理 | `preprocessor_fit_scope_must_equal_train` |
| 从 test 父样本创建训练增强 | `augmentation_parent_not_train` |
| 某类仅 2 家族，却要求覆盖三份集合 | `infeasible_class_group_support:rare` |

八项均在本次运行中按预期被挡住。每次故障后，正确方案的冻结 manifest 摘要保持不变。输入记录顺序整体反转后，分组方案也生成相同成员清单。

## 身份查表玩具基线

额外的 `identity_lookup_accuracy()` 故意只做一件事：记住 train 中每个 family_id 对应的类别；未见家族一律猜训练集中最多的类别，同票时按名称排序。

本次结果：

- 行随机划分：108 / 108 = 100%；
- 分组划分：36 / 108 = 1/3。

**这不是 3D 模型准确率，也不表示真实分组任务只能做到 1/3。**函数根本没有学习几何特征；它只是直接揭示“记住家族身份就能在泄漏测试上拿满分”的机制。真实模型可能利用真正可泛化的特征，也可能利用未被发现的捷径，需另行评测。

先看 `make_rows()`，确认独立单位和派生记录；再看两种 split 函数；随后读 `validate_assignment()` 和 `summarize()`，理解行级互斥与家族互斥的差别；最后看 `fit_preprocessor()`、增强约束及故障注入。
