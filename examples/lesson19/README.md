# 第 19 讲工程实验：把标签绑定到几何，而不只是给模型涂色

本实验使用三块人工构造的三角面，验证面级标签如何生成点级标签，以及忽略标签如何影响语义指标。它没有训练模型，也没有使用真实椅子资产；输出不能证明实际标注质量，不能替代人工审核。

## 文件

| 文件 | 用途 |
|---|---|
| `annotation_lab.py` | 可运行的 NumPy 示例及必要的边界检查 |
| `example-report.json` | 2026-11-27 在下述环境中实际生成的报告，含 12 个采样点及完整来源映射 |

已执行环境：Python 3.12.14、NumPy 2.3.5。只需 CPU，不下载模型或数据。

从仓库根目录运行：

```bash
python -m pip install "numpy==2.3.5"
python examples/lesson19/annotation_lab.py --output /tmp/lesson19-report.json
```

不带 `--output` 时只把 JSON 打印到终端。不使用 Python 的 `-O` 选项，因为该选项会移除教学验证用的 `assert`。

## 输入约定

- 资产局部坐标，右手系，Z 向上，坐标单位米，三角面面积单位平方米。
- 三角面的面积分别为 `1, 2, 1`；这不是一个真实可用椅子模型。
- 每个三角面必须只有一个确定的语义类别。跨语义边界的面应先细分、使用更细的表示或保留歧义，不能靠采样算法解决。
- 教学类 ID `0 = seat_demo`、`1 = back_demo`；它们不是任何公共数据集的正式 ID。
- `-1` 表示未标注，不代表背景。
- 本例训练策略仅使用 `reviewed == true` 且语义 ID 有效的点。其他项目可定义独立的伪标签训练策略，但应显式区分来源和权重。

## 输出数据结构

| 字段 | 形状/类型 | 含义 |
|---|---|---|
| `points` | N × 3 浮点数 | 表面采样点位置 |
| `source_face_id` | N 整数 | 对应当前几何版本的三角面行索引 |
| `barycentric` | N × 3 浮点数 | 在源三角面内的重心坐标，非负且总和为 1 |
| `semantic_id` | N 整数 | 直接继承源三角面的语义 ID |
| `reviewed` | N 布尔值 | 继承源面的审核状态 |
| `train_mask` | N 布尔值 | 本例政策下可进入监督损失的点 |
| `geometry_revision` | 字符串 | 教学几何版本 ID |
| `geometry_digest` | SHA-256 | 对坐标和面索引数组顺序敏感的绑定校验值 |

哈希先固定数组形状、字节序和数据类型，再按顺序编码顶点与面数组。因此，仅交换面数组的两行，即使渲染外观完全不变，也会拒绝旧标注绑定。这是有意设计的保守校验，**不是**用于几何去重的旋转不变指纹。生产数据还需保存标签本体版本、全局资产 ID、节点变换、实例表以及修订日志。

## 算法要点

先按面积比例选择三角面，再在选定面内按均匀面积分布采样。若两个独立随机数 r、s 都均匀取自 [0,1)，重心坐标取 `(1−√r, √r(1−s), √r s)`。三个顶点用这三个权重组合得到采样点。

三角面不是等概率抽取：面积为 2 的面应有面积为 1 的面两倍的抽样概率。随机种子是 19；12 个展示点只是一个很小的样本，不能据其频率判断采样器优劣。脚本另用 10,000 个点验证频率。

## 实际运行结果

三块面的期望概率为 `0.25, 0.50, 0.25`；本次 10,000 点的实际频率为：

```text
0.2547, 0.4901, 0.2552
```

源码执行并通过了来源标签对应、重心坐标重建、未标注排除、未审核排除、面顺序改变拒绝，以及全为 GT ignore 时指标返回 null 的检查。

指标反例输入：

```text
GT   = [0,  0, 1, 1, -1]
Pred = [0, -1, 1, 0,  1]
```

GT 为 `-1` 的最后一个位置不参与评测；第二个位置的 GT 有效，预测 `-1` 必须计为一次漏检。实际结果：

| 指标 | 结果 |
|---|---:|
| 有效 GT 数 | 4 |
| 类 0 IoU | 1/3 |
| 类 1 IoU | 1/2 |
| mIoU | 5/12 ≈ 0.416667 |
| Accuracy | 0.5 |
| 有效 GT 上预测弃权数 | 1 |

混淆矩阵的前两列是预测类 0、1，第三列单独记录弃权。**绝不能用 `(GT != -1) & (Pred != -1)` 作为评测掩码**，这会让模型通过不预测困难点提高分数。本例 mIoU 只平均 union 大于零的类别；正式评测必须使用目标 benchmark 的类别集合、空类与 ignore 协议。

实例反例中，四个点分别属于两把椅子，模型却输出一个合并实例。语义准确率仍是 1；合并掩码与每个真实实例的 IoU 都是 0.5，在严格 `IoU > 0.5` 的匹配规则下，没有匹配成功的实例。此处只演示匹配反例，不是完整 PQ/AP 评测器。

## 已知边界

1. 人工构造的语义和审核位不能证明真实标注正确。
2. 实验没有训练分割模型，没有实现跨网格标签投射或多视图自动标注。
3. 固定标签 ID 没有完整的类别本体和父子层次；正式数据需要独立 schema。
4. 输入假定三角面内语义一致；共享顶点跨部件时，不能以顶点多数票代替精确边界规则。
5. 本例点采样指标不等于直接按面计数的指标，生产评测需预先固定面积、点密度与聚合协议。
6. 同一个种子在固定环境下可复现；跨 NumPy 版本的完全相同随机序列不作为此实验的承诺。关键语义断言与理论 IoU 不依赖随机频率。

学习者完成运行、解释错误掩码为什么高估分数，并能说明几何换序如何破坏标签绑定后，才有相应实践证据。仓库中存在本脚本不代表学习者已经通过考核。
